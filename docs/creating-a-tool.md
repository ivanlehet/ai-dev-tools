# Creating a tool

Every tool is an independent **release unit**: its own Nx project, version, tests, package,
install/uninstall, and release. This guide shows how to add one.

## 1. Scaffold

```bash
npm run create-tool
```

The generator asks for:

- **type** — `skill`, `plugin`, `hook`, `agent`, `rule`, `prompt`, or `mcp`
- **name** — kebab-case, unique
- **target hosts** — one or more of `claude`, `cursor`, `codex`
- **disclosure** — capabilities (filesystem/shell/network/git/credentials/telemetry/…),
  permissions, side effects
- **license**, **initial version**, and the **official spec** you validated against

It then creates the project in the right place (single host → `tools/<host>/<type>/<name>/`,
multi-host → `tools/portable/<type>/<name>/`) with the full lifecycle wired up, and refuses
invalid names, unsupported type/host combinations, or undeclared permissions. It never leaves
a half-generated project.

## 2. What you get

```
<name>/
  <native manifest>          # SKILL.md | .claude-plugin/plugin.json | *.mdc | AGENTS.md …
  manifest/tool.json         # disclosure + policy metadata + targets (version stamped, do not hand-edit)
  install.sh · uninstall.sh · validate.sh   # detect OS + --host, scoped & reversible
  project.json               # lifecycle targets
  package.json               # the single authoritative version source
  tests/ · fixtures/
  README.md                  # includes the "Ethics & Security" section
  SECURITY-CHECKLIST.md      # attestation, must be fully checked
  CHANGELOG.md               # generated by nx release
```

## 3. Lifecycle targets

Every tool exposes the same targets (no placeholders, no fake success):

| Target | Meaning |
|---|---|
| `validate` | required files, schema, version consistency, disclosure, compliance, quality |
| `test` | meaningful behavioural/structural tests |
| `package` | deterministic artifact into `dist/tools/<name>/` + integrity checksum |
| `validate-package` | inspect the built artifact (prohibited files, checksum, version) |
| `install` / `uninstall` / `verify-install` | scoped, reversible, verifiable |
| `security-check` / `policy-check` | release-blocking policy gates |

Run them via Nx:

```bash
nx validate <name>
nx run <name>:package && nx run <name>:validate-package
nx run <name>:install -- --host claude
```

## 4. Versioning

Record intent with a **Version Plan**, never by editing versions by hand:

```bash
npm run create-version-plan     # nx release plan
```

SemVer is enforced by `policy-check`: adding a target host is a **minor**, removing one is a
**major**, and breaking security/privacy/permission changes never ship in a patch.

## 5. Multi-host (portable) tools

Keep one canonical source under `tools/portable/<type>/<name>/`. The `install.sh` maps it to
each host (`--host claude|cursor|codex`): the content is identical, only the target location
and registration format differ (e.g. MCP registers into `.mcp.json` for Claude/Cursor and
`~/.codex/config.toml` for Codex). Only claim a host in `targets` after its validator and
fixture pass.

## 6. Before opening a PR

`npm run verify` must be green, and `/security-review` + `/review` must show no blocking
findings. See [`POLICY.md`](POLICY.md).
